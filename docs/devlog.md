## 1. 데이터 수집·전처리

### 1-1. 목록 만들기: 분야별 병렬 작성 후 병합 검사
- 20개 분야 분류표(SCHEMA.md)를 먼저 고정하고, 7개 분야 묶음으로 나눠 동시에 작성 → `merge.py` 가 합치며 검사
- 검사에서 잡힌 것: 파일 간 **중복 id 3건**(미래에셋그룹·코닝·카카오페이 — 금융/기업집단, 소재/전자 경계), 파일 간 **끊긴 소속 15건**(AWS→아마존 등, 모회사가 다른 파일에 있어 작성 시점엔 비워 둠)
- 교훈: 분야 경계에 걸친 브랜드는 누가 가질지 규칙을 먼저 정해야 함. 병합 검사를 스크립트로 두니 이후 수정도 안전

### 1-2. 설명글: 이름 누수 막기
- 요약글에 브랜드·모회사 이름이 들어가면 임베딩이 **철자로 가까워짐**(초벌에서 이름만 임베딩했을 때 카길 → 캐딜락·캐드버리, 스타벅스 → 스포티파이·스팀)
- 규격에 "이름 금지"를 두고 `check.py` 가 한글·영문 이름·별칭·모회사 이름을 정규식으로 검사
- 작성자가 스스로 더 잡은 것: "온라인"에 LINE 의 한글 이름 '라인'이, "메타버스"에 '메타'가 들어감 → 검사기는 못 잡는 부분 문자열 누수

### 1-3. 설명글: 국적 누수 (가장 큰 전처리 발견)
- 증상: 무인양품 이웃이 비오레·가루비·야쿠르트(일본 식품·생활)
- 측정: 설명글 임베딩 상위 10 이웃 중 **같은 나라 53%**, 무작위 기대 18%
- 원인: 요약 1,603개에 "미국" 365회, "한국" 319회, "국내" 267회. 출신은 origin 묶음이 따로 있어 **국적을 두 번 세고 있었음**
- 조치: `embed/clean.py` 로 나라·지역·도시·"국내/해외"를 지우고 재임베딩(원문은 보존). 조사 붙은 꼴(미국산, 일본식, 국내에서는)까지 처리, "부산물·아로마·파리바게뜨"처럼 이름을 품은 낱말은 안 지우게 경계 검사
- 결과: 같은 나라 **53% → 30%**, 무인양품 → 아르켓·코스·헤이
- 남은 것: "사케·K-뷰티" 같은 문화 단서

### 1-4. 이름 임베딩 삭제
- 비교용으로 넣었던 "이름만" 모드: 모델의 브랜드 지식보다 글자 모양을 봄. 사용자 판단 "임베딩할 내용이 아니다" → 계산·뷰어·테스트에서 제거

### 1-5. 시가총액: LLM 추정 → 실제 시세
- LLM 이 적은 시총은 2025년 무렵 기억. 티커 685개로 Yahoo Finance 조회 → 677개 갱신
- 비교: 중앙 배율 1.02(대체로 맞음), 2배 이상 차이 26곳. 마이크론 250→1,044B, 삼성전기 10→75B — **다른 경로(info)로 재조회해 실제 값 확인** 후 반영
- 버그 기록: `yfinance` 의 `fast_info.get("market_cap")` 은 키 이름이 달라 조용히 None → 685개 전부 not_found. `fast_info["market_cap"]` 로 해결
- 표기 문제: `MAERSK.B` → Yahoo 는 `MAERSK-B.CO`, 옛 티커(ERJ→EMBJ). 실패 8곳은 추정값 유지하고 `caps.csv` 에 status 로 남김
- 하위 브랜드는 모회사 시총을 **0.7배 흐리게** 물려받음(킷캣이 곧 네슬레 규모는 아니므로)

### 1-6. Wikidata 대조: API 차단
- 첫 실행이 **429 Too Many Requests** 로 멈춤 → 속도만 늦춰도 계속 막힘
- 원인: Wikimedia 정책상 User-Agent 에 연락처가 없으면 차단. UA 에 GitHub 주소를 넣자 즉시 200
- 부수 문제: 막힌 옛 프로세스가 백그라운드에 남아 새 실행과 경쟁 → 찾아서 종료

## 2. 임베딩 설계·가중치

### 2-1. 빈 특징 처리
- B2B·기업집단은 가격이 없고 작은 브랜드는 시총이 없음 → 0으로 두면 "가격 없는 것끼리" 가까워짐
- **둘 다 가진 묶음만으로 가중 평균**, 공통 가중치가 0.5 미만이면 비례 감점. 단위 테스트로 고정

### 2-2. 가중치: 줄다리기의 발견
- "A 는 C 보다 B 에 가깝다" 정답 세트로 격자 탐색
- 같은 업종 문항을 다 맞히면 **다른 분야 이웃이 4% 로 떨어짐**(업종 맞히기가 됨). 상품 묶음을 올리면 6%
- 선택: 학습 문항 틀림 0 이면서 다른 분야 이웃 10% 이상인 조합(11%)
- 과적합 대응: 34 → 90 → 109문항, **학습/검증 분리**. 검증 문항은 탐색에 안 씀. 현재 검증 29문항 중 1개 틀림(몽클레르가 캐나다구스보다 구찌 쪽)
- 사람도 갈리는 문항(에미레이트: 라이언에어 vs 메리어트)은 `debatable` 로 따로 두고 강제하지 않음

### 2-3. 아슬아슬한 문항
- 파텍필립: 람보르기니 0.4560 vs 카시오 0.4558 → 압축 모델에서 뒤집힘. 정답 세트가 **여유(margin) 없이 통과**하는 문항은 작은 변화에도 흔들림 → 이후 margin 도 보고 싶음

## 3. 게임화(행선지4: Brand)

### 3-1. 워커에 모델 넣기
- 1,603×1,603 유사도표 5MB 는 워커에 못 넣음 → 요청 때 정답 한 줄 계산
- 설명·상품 1024차원을 PCA 로 줄였더니 순위 상관 **0.89**(기준 0.97 미달)
- 원인: 평균을 빼는 PCA. bge 벡터가 한 방향으로 몰려 있어 평균을 빼면 코사인 구조가 바뀜
- 평균을 빼지 않는 SVD 128차원 → **0.998**, int8 로 담아 0.997, 상위 10 겹침 95%
- 계산 시간: 정렬을 형식 배열로 바꿔 정답당 중앙 1.9ms(무료 워커 CPU 10ms 안)

### 3-2. 다른 세션과 겹침
- 포팅 도중 행선지 원본이 다른 세션에서 바뀜(쉬운 모드 → 하드 모드). 포팅은 `assert` 로 바꿀 문장을 확인하므로 즉시 드러남 → 최신 원본 기준으로 다시 포팅

## 4. 방향 수정: 1,603개는 너무 많다 (진행 중)

### 4-1. 플레이 후기
- 사용자: "내가 모르는 브랜드가 많아서 임베딩만 가지고 찾아가기 어려웠다"
- 해석: 점수를 받아도 **다음에 부를 이웃이 떠오르지 않음**. 순위 한 계단의 의미도 너무 작음(1/1,602)

### 4-2. 기존 등급으로 자르면 안 되는 이유
- LLM 이 매긴 tier=mega 소비자 브랜드 221개 — 크기는 맞지만 **한국 브랜드 5개뿐**(세계 매출 기준 편향)
- → 한국 사람이 실제로 찾아보는 정도를 재야 함: 한국어 위키백과 12개월 조회수

### 4-3. 실험 설계
- 규칙 3 × 크기 3 (150·200·300): `views`(조회수만) / `quota`(분야 쿼터 + 같은 그룹 2개 제한) / `blend`(한국·영어 조회수·언어 수 혼합)
- 오프라인 지표 비교표 + 플레이 테스트(`embed/play.py`)

### 4-4. 인지도 수집 v1 → v2 → 검증 (전처리 QA 사례 묶음)
| 단계 | 방법 | 드러난 문제 | 수치 |
|---|---|---|---|
| v1 | Wikidata 매칭 항목의 한·영 위키 문서 조회수 | 제품 브랜드가 빠짐(기업 항목만 매칭): 아이폰·인스타그램·챗GPT·자라·노스페이스 = 0. 엉뚱한 문서: 루이비통→LVMH, 페이스북→메타, G마켓→Qoo10 | 한국어 문서 1,054 |
| v2 | 위키에서 이름으로 직접 찾기, 넘겨주기 추적, 동음이의 제외, 월 중앙값×12 | 짧은·일반명사 이름이 딴 문서로: 삿포로·칭따오→도시, 이솝→아이소포스, 도브→비둘기과, 케이투→산. 표기 차이(바클레이즈↔바클리즈)를 공유 문서로 오판 | 인스타그램 0 → 58.9만/년 |
| 검증 | 문서의 Wikidata 설명·P31 로 기업·브랜드인지 판정, 버린 곳은 "이름+브랜드" 검색으로 재시도 | 재시도도 가끔 틀림(삿포로→삿포로 TV타워) | 버림 47 → 재시도 성공 29 |

- **속도**: 조회수 API 를 1건씩 부르니 초당 1건, 2,600건에 30분 넘게 예상 → 연락처를 담은 UA 로 **4갈래 병렬** 요청으로 바꿔 몇 분에 끝남. 이미 받은 응답은 캐시로 재사용
- **캐시 버그**: 캐시 파일 이름에 파이썬 `hash()` 를 썼는데 실행마다 값이 달라 재실행 때 캐시가 한 번도 안 맞음 → md5 로 교체
- **v1 첫 실행 오판**: Wikidata 는 요청 속도가 아니라 UA 연락처 누락으로 막고 있었음 (1-6)

### 4-5. 조회수는 친숙함을 재지 못한다
- 첫 비교표(규칙 4 × 크기 3)에서 목록을 열어 보니: 루이비통 월 579회, 샤넬 455, 코카콜라 626, 레고 612 — 누구나 아는 브랜드가 낮다

- 방송사·신문·통신이 22개로 쏠림(MBC 월 72만). 뉴스·주가로 튄 문서(퓨리오사AI, 한화오션)도 위로
- 분야 쿼터의 부작용: 최소 개수를 채우느라 물류·농업에서 야마토운수·미국우정청·호멜·타이슨푸드가 들어옴
- 그룹 2개 제한으로도 BMW·BMW그룹, 르노·르노코리아, 애플·아이폰이 같이 들어옴 — 사실상 같은 이름 두 번
